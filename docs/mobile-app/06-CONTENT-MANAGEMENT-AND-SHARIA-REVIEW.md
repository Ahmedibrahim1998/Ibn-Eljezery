# 06 — إدارة المحتوى الشرعي والمراجعة

> المحتوى الديني مسؤولية. لذلك **لا يُنشر أي درس أو ذكر إلا بعد اعتماد مراجع شرعي** من مشايخ الأكاديمية.

## 1. الأدوار في لوحة التحكم (Filament Shield — موجود بالفعل)
| الدور | الصلاحيات |
|------|-----------|
| `super_admin` | كل شيء |
| `content_editor` (كاتب محتوى) | إنشاء وتعديل المسودات وإرسالها للمراجعة — **لا ينشر** |
| `sharia_reviewer` (مراجع شرعي) | مراجعة واعتماد أو رفض مع ملاحظات |
| `publisher` (ممكن يكون الأدمن) | نشر المحتوى المعتمد للتطبيق |

## 2. دورة حياة المحتوى
```
 draft ──(إرسال للمراجعة)──▶ in_review ──(اعتماد)──▶ approved ──(نشر)──▶ published
   ▲                             │
   └──────(رفض + ملاحظات)─────── rejected
```
- أي تعديل على درس منشور يُنشئ **نسخة جديدة** (version + 1) تمر بنفس الدورة، والنسخة القديمة تبقى ظاهرة حتى اعتماد الجديدة.
- تسجيل من راجع ومتى (`reviewed_by`, `reviewed_at`) — للمساءلة.

## 3. Filament Resources الجديدة
| Resource | ملاحظات |
|---------|---------|
| `LearningSectionResource` | ترتيب بالسحب (sort_order) |
| `LearningSubjectResource` | فلتر بالقسم والمذهب والمستوى |
| `LessonResource` | محرر نصوص غني (RichEditor)، رفع صوت، أزرار: إرسال للمراجعة / اعتماد / رفض / نشر حسب الدور |
| `AzkarCategoryResource` / `AzkarResource` | حقل التخريج إلزامي |
| `ReciterResource` | |
| `AppVersionResource` | فرض التحديث |
| صفحة Dashboard | عدد المحتوى في انتظار المراجعة، عدد الأجهزة النشطة |

## 4. معايير كتابة المحتوى (تُتفق مع المشايخ)
- كل حديث يُذكر معه **التخريج ودرجة الصحة**.
- الآيات داخل الدروس تُكتب بصيغة مرجعية (مثال `[[2:255]]`) والتطبيق يعرضها من النص المدمج — **لا تُكتب الآيات يدوياً** لتجنب الأخطاء.
- في الفقه: تحديد المذهب أو "قول الجمهور" بوضوح، والإشارة للخلاف المعتبر عند الحاجة.
- لغة مبسطة مناسبة للمستوى المحدد.
- المراجع في آخر الدرس.
